Identify it.

A workbench for equipment you own or are authorised to service. It reads what a device reports about itself — an IDCODE, an RDID, a ROM id, a CAP file, a firmware dump, a S.M.A.R.T. log — and turns that into a substitution decision with every gate enumerated. It does not guess from a marking on a package, it does not sniff a network it cannot reach, and it will not help defeat a read-out protection.

The dossier

The premise this app was asked to start from was an agent promiscuously sniffing the network and detecting devices. A web page cannot do that — no raw sockets, no promiscuous mode, no ARP table, and the browser hides your own LAN address behind an mDNS placeholder. The first panel below says exactly what is blocked and what remains. What remains is hardware you physically hand the page, and the unit of knowledge is a dossier: one per device you own, with every finding ranked by how it was obtained.

UEFI, BIOS ROM arithmetic and the POST card

Three layers that are routinely conflated: the flash (what the SPI chip holds), the regions (what the descriptor carves it into) and the volumes (what the firmware parses). Getting the layer wrong is how a repair writes one board's MAC address onto another. Below that, a virtual POST card: feed it a captured code trace and it tells you whether the board stalled, retried, or handed off.

1-Wire, iButton and the weather station

A weather station is the most common field equipment whose sensors are not on I²C or SPI but on a one-wire bus with parasitic power, a 48-bit serial number per device and a CRC-8 over the ROM. When one fails you are usually not debugging a chip — you are debugging a pull-up resistor, a cable length and a checksum. Decode a ROM id, check a scratchpad, or work through the bus-fault table.

Java bytecode & Java Card

Java bytecode is the one instruction set here that is manufacturer-independent by design: the same CAP file runs on an NXP JCOP, an Infineon SECORA, a Thales card and a simulator, because the ISA is specified rather than reverse engineered. When the silicon underneath is unobtainable — which is the whole premise of a substitution repair — the bytecode layer is the part of the stack that survives the change of manufacturer. That is why this sits next to JTAG and not in some other project.

Substitution & repair planning

A substitution is a set of gates. A hard gate failed means the board or the replacement part is damaged; a soft gate failed means something subtler breaks — a bootloader whitelist rejects the part, a status-register write locks the array, a calibration page is lost. A gate you cannot answer is recorded as unknown and counted against confidence. It is never silently treated as a pass, because that is exactly how a confident wrong substitution kills a board.

Prime lattice

Not decoration. Primes appear in hardware work in four places where getting them wrong costs a day: stride aliasing against a bank count, LFSR and CRC tap selection over GF(2), capacity arithmetic on non-power-of-two parts, and coprimality of wear and polling periods. The sieve here is verified against Project Gutenberg ebook #65, The First 100,000 Prime Numbers, whose 100,000th prime is 1,299,709.

References, evidence discipline and scope

Every row in every table in this app carries an evidence tag. std is read out of a published standard or vendor datasheet. tool is read out of an open-source tool's own tables and quoted. report is a third-party observation. recall was transcribed from memory and not verified against the source — those rows are rendered with a warning stripe and are excluded from automatic decisions. A fabricated citation is worse than no citation.

CHIPWRIGHT — offline HTML5. No server, no keys, no upload: a dump you drop here is analysed in this page and never leaves it. The tools read, identify, verify and reconstruct. They are for equipment you own or are authorised to service. Read-out protection, secure boot and debug authentication exist to stop exactly what a JTAG tool makes easy; this workbench tells you when a part is documented as protected and stops there. It contains no bypass, no fuse-defeat procedure and no per-device unlock recipe.

Run node tools/verify_chipwright.mjs for the headless proof: CRC-32 and CRC-8 check values, the sieve against Project Gutenberg #65, JEP106 parity across the vendor table, the TAP simulator's eight behavioural suites, the GF(2) tap table verified two ways, ISA round-trips, and the DOM-id contract between this page and js/cw-app.js.
