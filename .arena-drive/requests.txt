# Google Drive backup artifacts to pull onto a runner, one per line:
#
#   <drive-file-id> <output-name> [expected-size]
#
# Sizes are Drive's own reported byte counts, read from the API on 2026-10-04.
# A mismatch rejects the file rather than writing something truncated.
#
# Files land in .arena-drive/payload/, which is gitignored. The tarballs are up
# to 96 MB and must NEVER be committed — the workflow commits only the manifests
# (small, and useful provenance on their own) and the delta the diff identifies.
#
# NOTHING HERE WORKS UNTIL THE FILES ARE LINK-READABLE. Drive serves
# `uc?export=download` only for files shared with "anyone with the link"; for
# anything else it returns a sign-in page, which fetch.py reports as NOT-SHARED.
# Granting that access, and revoking it afterwards, is a deliberate human step.
# Sharing just the two .sha256 manifests is enough for the full file-level diff
# — the tarballs are only needed to actually restore bytes.
#
# ---------------------------------------------------------------- manifests
# Checksum lists. These are what make the rsync-style comparison possible
# without moving a single tarball: ~1 KB of hashes per 100 files.
#

# 25-file chipwright workbench that exists nowhere in Git.

#
# 2026-09-29 snapshot, 1342 files, commit 6635490 — the newest full snapshot.
10cPMbBD4ckfP6jnBz8f3YXdXmdgBhVTj  Html5-file-manifest-2026-09-29-6635490.sha256  138630

# 2026-09-28 snapshot, 1313 files, commit ee1ec85 — holds 559fb69, the lost

# ---------------------------------------------------------------- payloads
