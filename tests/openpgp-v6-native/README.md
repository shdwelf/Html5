# Independent native v6 synthetic controls

This **test-only** Go executable uses `ProtonMail/go-crypto/openpgp/v2` v1.5.2,
separate from both OpenPGP.js distributions. It is not a browser dependency,
production CLI, owner-key importer, PGPony component or a claim about Proton VPN.
No cryptographic primitive is implemented here.

## Run

Use a current reviewed Go SDK supporting `go 1.23.0` modules and Node 22. CI pins
the SDK and action SHAs. From the repository root:

```sh
npm ci --ignore-scripts --no-audit --no-fund
# Place the executable outside any app, release artifact or source fixture tree.
(
  set -eu
  reader_dir="$(mktemp -d)"
  trap 'rm -rf -- "$reader_dir"' EXIT
  (
    cd tests/openpgp-v6-native
    export GOTOOLCHAIN=local GOFLAGS=-mod=readonly
    go mod download
    go mod verify
    go build -trimpath -mod=readonly -o "$reader_dir/html5-openpgp-v6-interop" .
  )
  OPENPGP_V6_GO_READER="$reader_dir/html5-openpgp-v6-interop" REQUIRE_OPENPGP_V6_NATIVE=1 node --test tests/openpgp-v6-native-policy.test.mjs tests/openpgp-v6-native-interop.test.mjs
)
```

The shell trap removes the executable directory. The test runner separately
removes its private temporary key/data directories
in `finally`. Removing files/references does not guarantee physical secure
erasure or zeroization of engine/OS copies. No owner key/passphrase is needed.

Without the executable, the four native cases are explicit optional local
skips. `REQUIRE_OPENPGP_V6_NATIVE=1` makes missing/broken reader execution a
failure. A separate policy suite tests both paths. CI builds the reader in the
same job, requires all four native cases and uploads no keys, secrets or data.

## Narrow evidence

- Fresh v6 Ed25519 primary / X25519 subkey generated by Go; both full 64-hex
  fingerprints, direct self-signature and encryption binding validated by both
  shipped JS readers. Fresh JS certificates are independently validated by Go.
- The **actual streaming release encryption helper**, not a second mock writer,
  encrypts 384+ KiB of binary/Unicode/CRLF data to the Go-generated recipient.
  Go independently recovers exact bytes through v6 PKESK / SEIPDv2 /
  AES-256-OCB, including the final authentication tag.
- Reverse native encryption to a JS-generated recipient negotiates
  **AES-256-GCM** and decrypts exactly with both JS distributions. This upstream
  writer prefers common GCM even when its default mode is OCB; the harness
  asserts GCM rather than altering a recipient's signed preferences. The
  release-helper direction still requires **AES-256-OCB**. Actual packet
  versions, per-direction cipher/mode IDs and the complete encryption-subkey
  fingerprint are asserted, not inferred from armor labels.
- Modified ciphertext/final tags, truncation, changed fingerprint bytes outside
  the short key ID, trailing outer junk and an unrelated secret fail. Native
  plaintext is committed with exclusive mode-0600 creation **only after EOF
  authentication**; an existing destination is never overwritten.
- Secret/mixed/bundled, v4, revoked, expired, unbound, signing-only and wrong or
  short fingerprint inputs are negative controls, not salvage candidates.

The Go preflight intentionally accepts **one** Ed25519 primary and **one**
X25519 subkey. It is a test profile, not a new production import policy. Test
secret packets are unprotected, short-lived throwaway keys in OS-private
mode-0700 directories and mode-0600 files; protected-v6-secret export/unlock is
not an app feature or a gate claimed by this harness. No actual owner identity,
keyring, private key, passphrase, attachment or cloud archive enters these tests.

A passing run establishes independent command-line/library interoperability
only for the tested versions and two explicit packet profiles. It does **not** establish
owner-key recovery, every v6/PQC algorithm, native GnuPG v6 support, mobile/GUI
client compatibility, APK delivery or a complete cryptographic security audit.
The existing classic-v4 and Android/device controls remain separate and are
not disabled or replaced.

Dependencies are isolated in this directory with exact `go.mod` / `go.sum`
versions. `go mod download`, `go mod verify`, `-mod=readonly`, a local-only
SDK selection, no replacement directives and the runtime build-info check
bind the test dependency. Module-checksum verification is not a security audit
or a claim that the SDK/test binary is reproducibly built. Upstream source
provenance, licensing and the local SDK/CI SDK distinction are recorded in
[`docs/openpgp-v6-native-interop-2026-11-17.md`](../../docs/openpgp-v6-native-interop-2026-11-17.md)
and its linked manifest.
