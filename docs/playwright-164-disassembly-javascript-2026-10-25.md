# Playwright 1.64 — disassembly and conversion to JavaScript

*2026-10-25 · Round 52 · The ask: “Disassemble playwright 1.64 and
convert to javascript; continue backlog.” Target pinned:
`playwright-core@1.64.1` (npm latest at time of work).*

Two deliverables: a **disassembly** of the shipped package (module-level,
repeatable) and a **conversion** — the slice of Playwright this repository
actually uses, re-implemented in dependency-free JavaScript talking raw
CDP, with the repo's one Playwright consumer converted to it.

## 2 · Disassembly

### 2.1 Entry chain

```
index.js ── require('./lib/bootstrap')          Node ≥ 20 gate (+ optional PW_PROFILE_DIR inspector profiling)
         └─ module.exports = require('./lib/coreBundle').inprocess.playwright
index.mjs ─ ESM re-export of the same in-process driver
cli.js ──── 'playwright-core' bin (browser install / CLI daemon)
```

There is no per-module `lib/` tree: the whole driver is two esbuild
bundles. Crucially, **esbuild's module banners survive** (`// packages/…`,
`// node_modules/…`), so the bundle disassembles cleanly module-by-module
without a source checkout — that is what the disassembler exploits.

### 2.2 Module census (from the banners)

| `packages/playwright-core/src/tools` | 87 | 12,250 | CLI daemon, MCP, dashboard, trace tooling |
| `packages/playwright-core/src/client` | 51 | 7,109 | the public API objects (`locator.ts`, `download.ts`, `fetch.ts`, `cdpSession.ts`…) |

Largest modules overall: `protocol/src/validator.ts` (3,228 L),

`lib/utilsBundle.js` — 3.1 MB, 86,079 lines, **627 modules**, almost all

Plus `lib/serverRegistry.js`, Vite-built UIs (dashboard / recorder /
traceViewer / htmlReport) and `lib/webp_codec.wasm` (565 KB) for
screenshot encoding.

### 2.3 Architecture, as the bundle tells it

```
your script ── client (51 modules; ChannelOwner objects: Page, Locator, Download…)
            ⇄ Playwright channel protocol (packages/protocol validator)
            ── in-process (index.js) or out-of-process (src/remote, driver process)
            server registry (browsers.json pins) ── server (154 modules)
              ├─ Chromium: crPage ⇄ CDP over --remote-debugging-pipe
              ├─ Firefox:  Juggler protocol (patched Firefox)
              └─ WebKit:   wkPage ⇄ WebKit protocol (patched WebKit)
            injected scripts (7 modules) run in-page for selectors/actionability
```

Browser pins (`browsers.json`): Chromium r1248 = **Chrome for Testing
156.0.8078.4**, Firefox r1555 = 157.0, WebKit r2370 = 27.2. The CDP type
surface ships as `types/protocol.d.ts` (generated by
`utils/protocol-types-generator`): **59 CDP domains** — the same protocol
the conversion speaks directly.

## 3 · Conversion to JavaScript

**Deliverable:** [`tools/wiki-workspace/cdp-browser.mjs`](../tools/wiki-workspace/cdp-browser.mjs)
— the Chromium slice, re-implemented in plain dependency-free JavaScript
(Node built-ins + the global WebSocket), exposing the Playwright-shaped
API the repo's consumer uses. Playwright's client→channel→server
indirection collapses into direct CDP; its injected-scripts trick is
kept, at smoke scale.

| Playwright call | CDP conversion |
| --- | --- |
| `chromium.launch({executablePath, args})` | spawn with `--remote-debugging-port=0`, parse `DevTools listening on ws://…` from stderr, WebSocket attach |
| `browser.newPage({viewport})` | `Target.createTarget` + `Target.attachToTarget {flatten:true}`; `Emulation.setDeviceMetricsOverride` |
| `page.goto(url)` | `Page.navigate` + await `Page.loadEventFired` |
| `page.evaluate(fn, arg)` | `Runtime.evaluate` of `(fn)(JSON arg)`, `awaitPromise`, `returnByValue` |
| `page.locator(css)` `.count/.click/.fill/.check/.innerText/.first()` | injected `querySelectorAll` pick expressions; fill uses the prototype value setter + `input`/`change` events (React-safe pattern) |
| `page.getByRole(role, {name})` | injected `roleOf`/`nameOf` picker (tag→role map, `aria-label`/text name, string-substring or RegExp match) |
| `page.waitForSelector/waitForFunction/waitForURL` | 100 ms polling over `Runtime.evaluate` / `location.href` |
| `page.screenshot({fullPage})` | `Page.captureScreenshot` (+ `Page.getLayoutMetrics` clip) |
| `page.waitForEvent('download')`, `download.path()` | `Browser.setDownloadBehavior {eventsEnabled:true}` + `downloadWillBegin`/`downloadProgress` tracking |
| `locator.setInputFiles({name, buffer})` | temp file preserving the payload name + `DOM.setFileInputFiles` |
| `page.on('pageerror')` / `page.request.get(url)` | `Runtime.exceptionThrown` / Node `fetch` |

**Converted consumer:** [`tools/wiki-workspace/browser-smoke.mjs`](../tools/wiki-workspace/browser-smoke.mjs)
no longer requires `playwright-core` at all; only a Chromium binary
remains external (`CHROMIUM_EXECUTABLE` or `@sparticuz/chromium`), which
matches how `tests/lib-browser.mjs` already sources browsers.

### Defects found and fixed in-round

1. **Lambda args deadlock.** `@sparticuz/chromium`'s default `args`
   (`--single-process`, `--headless='shell'`, …) hang the Target/DevTools
   flow — the first real-browser run stuck for 10 minutes with a live but
   mute browser. The test uses the repo's curated arg set (as
   `lib-browser.mjs` does).
2. **Dual download events.** Chrome reports each download on both the
   Page session and the browser target; registering both overwrote the
   waiter map entry, so `download.path()` never resolved. Downloads are
   now deduplicated by `guid`.
3. **Upload filename drift.** The `setInputFiles` temp file initially
   carried a timestamp prefix, so `input.files[0].name` lied to the page;
   the payload name is now preserved exactly (unique temp *directory*
   instead).

### Verification

- `tests/playwright164.test.mjs` — **11/11**: disassembler on synthetic
  bundles + the committed-register pins (414/627 modules, server 154 /
  client 51, Chromium r1248 / 156.0.8078.4, 59 domains); CDP transport
  correlation, evaluate serialization, `waitForFunction` polling, goto /
  `loadEventFired`, `pageerror`, locator count/timeout, download waiter,
  role-picker expression — over a scripted fake transport.
- `tests/playwright164-browser.mjs` — **6/6 in real Chromium**
  (HeadlessChrome 153.0.8010.0 via `@sparticuz/chromium`): goto/fill/
  click/waitForFunction, evaluate-with-arg, checkbox, `getByRole` by
  accessible name, visibility `waitForSelector`, hash `waitForURL`, PNG
  screenshot bytes, attachment download bytes on disk, `setInputFiles`
  filename visible to the page, zero `pageerror`s. Skips cleanly when the
  browser deps are absent.
- The converted `browser-smoke.mjs` is syntax-checked and its entire API
  surface is what the two suites above exercise; its full run additionally
  needs the wiki JAR server up (Java toolchain), which was out of scope
  for this round — not claimed as run.

### Honest limits (not converted)

Firefox/Juggler and WebKit drivers; Playwright's actionability engine
(auto-wait for stable/hit-target — the conversion polls for existence
and, for `waitForSelector`, visibility); tracing, HAR, video; network
interception; multiple contexts / storage state; the test runner,
codegen, dashboard and MCP tools (the 87 `src/tools` modules); the
out-of-process channel protocol. `scripts/wormhole-fetch.mjs` still uses
full `playwright` on the operator's machine, deliberately untouched.
