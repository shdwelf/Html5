These are the two cheat/hint schemes the backlog’s “Game Genie and Game Wizard and

## 1 · Universal Hint System (`.uhs`, 88a→96a)

Format facts (Stefan Wolff’s [UHS2HTML primer](https://www.swolff.dk/uhs/),
[Vhati/OpenUHS](https://github.com/Vhati/OpenUHS), [Tormen/my-uhs](https://github.com/Tormen/my-uhs)):
line-based header + link tree + hints; hunks carry a type (`link`, `nesthint`, `text`,
`hyperpng`, …); files end with a 16-bit CRC. Three distinct obfuscations:

### 1a · 88a simple transform (hints, standalone hint nodes)

No key. Per byte: `c < 80 ? 2c − 32 : 2c − 127` (skip bytes `< 32`). The inverse —
needed for authoring/round-trip — is `p even ? (p+32)/2 : (p+127)/2`. The split at 80
is exact: the lower arm produces even plains, the upper arm odd plains.

| ciphertext | plaintext | source |
| --- | --- | --- |
| `gHrGtGs iqrGr` | `Opening Scene` | published (primer) |
| `kIpHHtGs jH JDr apyr` | `Wrapping Up the Case` | published (primer) |
| `kDpJ Bw d Bw tG JDr wCCtqr` | `What do I do in the office` | published (primer) |
| `4w{ Bw d ryqpHr CIwv JDr JDzsy` | `How do I escape from the thugs` | published (primer) |
| `4w{ Bw d pIIryJ 3pIGDpv` | `How do I arrest Farnham` | published (primer) |

### 1b · Nest-keyed transform (nesthint / incentive nodes)

Key from the master subject title (e.g. the game name):

```
key[i] = (ord(title[i]) + "key"[i % 3] ^ (i + 40)) mod* 96→printable   (* while >127: −96)
plain[j] = (ord(cipher[j]) − (key[j % klen] ^ (j + 40)))  while <32: +96
```

Known-answer vector (generated by the upstream `my-uhs` functions, re-derived here;
title `Borrowed Time`, key `[37, 91, 101, 82, 88, 107, 74, 78, 105, 78, 96, 87, 100]`):

| ciphertext | plaintext |
| --- | --- |
| `\"T'}Tk!L"WrU` | `Opening Scene` |
| `dzP-4Js!B?Vspy{r~iV1!Zvhz*F8UI` | `What do I do in the office? 42` |

### 1c · Text-hunk transform (binary tails after the `0x1A` separator)

Same key, but the index feeding **both** the key lookup and the XOR offset is
`co = j % klen` — the offset repeats with the key instead of growing with position:

```
plain[j] = (ord(cipher[j]) − (key[co] ^ (co + 40)))  while <32: +96
```

| ciphertext | plaintext |
| --- | --- |
| `\"T'}Tk!L"WrU` | `Opening Scene` |
| `dzP-4Js!B?Vspv o-|K$p_%[gUL2#K` | `What do I do in the office? 42` |

The two variants agree below `klen` (13 here) and diverge after it — the second pair
is the discriminator test in `tests/uhs-gamegenie.test.mjs`.

**CyberChef/cipher-machine recipe shape:** *From charcode → subtract keystream
(`key[i%klen]^(i+40)` or `^(co+40)`) → wrap +96 → to charcode*, with an optional
front step *title → generateKey*. The 88a arm is two *Fork/Multiply* branches on
`< 80`. All three are safe to expose in the lecture hall: they exist to stage
spoilers, and no UHS file protects anything.

## 2 · NES Game Genie

Code = scrambled `address / value / [compare]`; 6 letters (no compare) or 8.
Letter table `A P Z L G I T Y E O X U K S V N` = hex `0..F`. Port source:
[satoshinm/nes-game-genie](https://github.com/satoshinm/nes-game-genie) `gg.js`
(master @ `7eedc28b`); format background [NESdev](https://www.nesdev.org/wiki/Game_Genie)
and [gamehacking.org schemes](https://gamehacking.org/library/114).

```
value   = (d0&8)<<4 + (d1&7)<<4 + (d0&7)            [+ d7&8 | d5&8]
address = (d3&7)<<12 + (d4&8)<<8 + (d5&7)<<8
        + (d1&8)<<4 + (d2&7)<<4 + (d3&8) + (d4&7)   (15-bit CPU address, $8000-based)
compare = (d6&8)<<4 + (d7&7)<<4 + (d5&8) + (d6&7)   (8-letter codes only)
wantskey= d2 >> 3
```

| code | address | value | compare | wantskey |
| --- | --- | --- | --- | --- |
| `SLXPLOVS` | 4387 (`0x1123`) | 189 (`0xbd`) | 222 (`0xde`) | yes |
| `SXIOPO` | 4569 | 173 | — | no |
| encode `0x1123, 0xbd, 0xde` | | | | → `SLXPLOVS` |

**Recipe shape:** *Match/replace on the letter table → bit-interleave per the
scramble above*. SNES/Genesis/Game Boy variants use different scrambles
(SNES: value in clear + 24-bit transposition `ijklqrst opabcduv wxefghmn`) — open
fix-up: add their vectors from `ascenderx/gamegenie` or `jdratlif/ggencoder-java`
before claiming those rows (not invented here).

## 3 · What is deliberately absent

- **Game Wizard** has no portable code format (it edits live DOS memory); the
  archival notes live in the round-1 doc, and VOGONS’ `ems=false` finding is the
  only “recipe” there is for running it under DOSBox.
- No UHS **encoder** for 88a is published upstream (readers only); the inverse in
  the tool is arithmetic fact, checked by round-trip against the published pairs.
- The SNES/Genesis/Game Boy Game Genie rows are marked UNVERIFIED until vectors
  are taken from an upstream implementation, per the house rule in
  [`GHIDRA_COOKBOOK.md`](GHIDRA_COOKBOOK.md).
