Wayback's **displayed** `telnetbbs.com` captures are [2004-03-22 ROAR parking](https://web.archive.org/web/20040322033204/http://telnetbbs.com:80/), [2011-02-02](https://web.archive.org/web/20110202022148/http://telnetbbs.com/) and [2017-09-25](https://web.archive.org/web/20170925035324/http://telnetbbs.com/) 301 redirects to the Guide, [2021-12-23 directory listing](https://web.archive.org/web/20211223223001/http://telnetbbs.com/), [2023-01-20 directory listing](https://web.archive.org/web/20230120090534/http://telnetbbs.com/), and [2025-07-10 parking](https://web.archive.org/web/20250710015211/http://telnetbbs.com/). | A directory can identify candidate servers or a domain's *observed* redirect history. The [repo's capture viewer](bbs-viewer-and-netcat-capture.md) can process a **lawfully obtained, separately sourced** ANSI session offline. The existing sample BBS is a simulation, not an historical transcript. | `telnetbbs.com` is not evidenced as a longitudinal BBS-message archive. A domain's redirect or entry in a contemporary guide is not a transcript or evidence of an individual's presence. No external BBS was dialed in this sandbox. |
| **FidoNet:** the [FTSC FTS-5000 rev. 5 nodelist standard](http://ftsc.org/docs/fts-5000.005) describes the hierarchy, distribution files and node details; [FTS-1026 rev. 1](http://ftsc.org/docs/fts-1026.001) specifies Binkp/1.0 session transfer over reliable connections, with default TCP **24554**. | A dated, rights-cleared *nodelist* can support node/admin hierarchy observations; a Binkp session can exchange mail bundles. The [local-only adapter](historical-network-fidonet-adapter-2026-10-22.md) parses user-supplied lists/diffs without making them a public bulk dataset. The standard's public-domain statement is about the **standard**, not a blanket license for all distributed nodelists. | A nodelist is not a physical link measurement or chat log. Binkp is a mail-transfer protocol, not EFnet. Don't auto-merge users or addresses with IRC nicknames or publish restricted nodelists from a standards citation. |
| **BBS real-time doors:** [uMRC's own README](https://github.com/codefenix-dev/uMRC/blob/main/README.md) calls it a DOOR32.SYS-compatible Multi-Relay Chat BBS client, with a bridge to a separate MRC host. | Some BBSs support real-time networked chat *in addition to* posts and FidoNet mail; the door's documentation is evidence of one implementation. | MRC presence is not evidence of FidoNet traffic or a bridge to EFnet `#pub`; no such bridge or target conversation was located. |
| **Hotline:** the [Hotline Tracker Protocol](https://github.com/mierau/hotline/wiki/Hotline-Tracker-Protocol) returns server records (address, port, user count, name and description) via default TCP **5498**. [BigRedH's About page](https://tracker.bigredh.com/about.php) says it merges other trackers, periodically indexes **guest-visible file and folder metadata**, does not download files, offers an opt-out, and retains displayed user names for only 30 days. | Operator-described server/file-index *metadata*, with explicit timing and visibility limits, can be a discovery lead. An archived tracker capture must be dated to its **displayed** capture rather than an assumed request timestamp. | A tracker is not a message archive or an unrestricted census of private files. A matching server or filename is not proof of participation in an IRC or BBS conversation. Respect removal/opt-out policies. |
| **OpenPGP keyserver:** [keys.openpgp.org's Hagrid API](https://keys.openpgp.org/about/api/) supports fingerprint/key-ID lookup, opt-in **exact email** lookup and verified-address publication; the [repo comparison](openpgp-keyserver-working-list-2026-11-07.md) records dated Ubuntu/PGPkeys/Hagrid observations and their non-equivalent replication policies. [RFC 9580](https://www.rfc-editor.org/rfc/rfc9580.html) supersedes RFC 4880 for current OpenPGP packet formats. | Distribution and fingerprint comparison **after** an independently trusted verification path. An opt-in email lookup can show control of that address at a point in time, not control of an IRC nick. | A found key/User ID, signature-looking text or nickname match is not real-world identity proof, signature verification or historical network membership. We made **no private-identity key queries or uploads** in this pass. |

### EFnet `#pub`: search result, not a reconstructed conversation

For the **initial** request reviewed in this section, the scope was **EFnet channel `#pub`** with nicknames `shdwfear`, `shdwdruid`, and `shdwfear_`; the later `#2600`/`enocia` and `#nsl`/`shdwelf` follow-ups are documented separately. As of this review, **zero authenticated historical `#pub` conversations involving those handles have been recovered**. This is a statement about the reviewed evidence, **not proof no logs exist**.

- [Netsplit's EFnet `#pub` directory page](https://netsplit.de/channels/details.php?room=%23pub&net=EFnet) says its channel entry was registered from web requests on **2025-06-06**. It supplies no historical dialogue, speaker authentication, or evidence for an earlier date. Its page may show changing topics/stats; none were used as a retroactive archive.
- [Archive Team's IRC documentation](https://wiki.archiveteam.org/index.php/Archiveteam:IRC) explicitly notes that IRC messages are transient and some channels are not logged. Its linked EFnet archive is for selected channels, mostly historical through October 2020. The [public irclogger channel index](https://archive.fart.website/bin/irclogger_logs) lists selected channels but not `#pub`; its absence from **that index** does not exclude private or independent logs.
- The [EFnet nickname/channel FAQ](https://www.irchelp.org/ircd/efnetfaq.html#q2) says nicknames and channels are not registered identities. A same-spelled nick in another dataset is therefore not sufficient to attribute words to a person. Indexed false positives included an unrelated **2006 `#ictf` nick listing** (not a target-channel message; [source index](https://github.com/scy/scytale.name/blob/5b4c5c255d72cca85ea0829b6371b8da9b218e29/files/2006/12/ictf/iCTF-%23ictf.log)) and an unrelated [W3C `#pub` meeting log](https://www.w3.org/2021/03/18-pub-irc). Neither is an EFnet `#pub` conversation. **Do not quote them as such or join identities based on a filename/nick.**
- Searches for the three exact handles alongside `EFnet`, `#pub`, and log/archive terms, plus indexed code searches, yielded no authenticated target transcript. Guessed log endpoints and a channel-statistics page returned 404/500; these failures are not evidence of absence. We did not invent a dialogue, infer a timeline, or place any third-party transcript into the repository.

**If an owner-controlled client log or channel operator archive becomes available:** keep the raw file and any private excerpt in the owner's Drive, record source owner, capture method and timezone, hash original bytes, preserve line order and neighboring context, verify channel **and** network per session, and distinguish nick text from proven identity. Publish only the non-sensitive provenance/outcome here after a rights review. No private `#pub` excerpt exists to upload now.

## Next evidence gates and privacy boundary

1. For any candidate historical edge, archive **its own dated primary record** and record whether it is a nodelist membership, a tracker listing, a BBS transcript, a message, or an authenticated IRC log. Do not infer social contact from co-listing or collapse FidoNet/Hotline/EFnet/ARPANET into one undated graph.
2. If the user supplies a lawful EFnet `#pub` log, verify network/channel/timezone and authenticity before quoting or attributing; keep original bytes and genuinely recovered private excerpts **in Drive**, not Git. Currently there is **no** such recovered excerpt.
3. Repair/test candidate CyberChef links as **new, attributed versions**, not retroactive validations of the Drive originals; see the [31-row audit](cyberchef-drive-recipe-audit-2026-11-13.md). Public reports may cite books and specifications, but this repository does not contain the private export or a recreated target conversation.
