# Public IRC archive check: `#2600`, `shdwfear`, `enocia`

**Review date: 2026-11-13.** Follow-up to the earlier [EFnet `#pub` source review](historical-networks-and-source-leads-2026-11-13.md). This check expands the search to 2600's IRC network and public cross-network archives. It is **not** a transcript, claim of exhaustively searching every IRC server, nickname-owner identification, or test of live nick presence. Nicknames are case-insensitive for the relevant searches; `shdwfear` and `enocia` were searched as **separate strings**, not assumed to be aliases or people.

## Exact-handle leads versus verified conversation

1. **`shdwfear`: a different channel's nick listing, not `#2600`.** An indexed [2006 UCSB iCTF `#ictf` log](https://github.com/scy/scytale.name/blob/5b4c5c255d72cca85ea0829b6371b8da9b218e29/files/2006/12/ictf/iCTF-%23ictf.log) has the case-insensitive string `[solo]ShdwFear` in nickname-list entries (source lines **121–122**) and a disconnect event (line **1502**). The same file mentions SlashNET and later points participants to `bergman.cs.ucsb.edu` for `#ictf`. There is **no message spoken by that nick in this file**; the list and disconnect do not demonstrate identity, 2600net/EFnet participation, or any conversation with `enocia`. Do not read `[solo]` as part of an identity verification scheme.
2. **Other indexed `shdwfear` text is not an authenticated IRC log.** An [SDF Gopher index mirrored in a GitHub benchmark fixture](https://github.com/xvxx/phetch/blob/d0b503ebcf4b1992ca40906c03bba96b78ffd7ae/benchmarks/benches/sdf.txt) lists `shdwfear` as a 2017 Gopherspace entry; it says nothing about IRC. A [Reddit `r/NSL` search hit](https://www.reddit.com/r/NSL/comments/1njjcb/httplinksmkt1985comcttkn89msnjgznzcyoas2rmjc2mtg4n/) displays a snippet formatted `15:18 < shdwfear>`, but direct page and JSON reads returned **HTTP 403**. Without an independently readable original, channel, network, date, surrounding lines, or provenance, this is **only a low-confidence search lead**, not quoted dialogue; do not follow its suspicious outgoing link or attribute it to `#2600`. The later [EFnet `#nsl` check](irc-nsl-shdwfear-shdwdruid-shdwelf-source-check-2026-11-13.md) assesses the same Reddit lead in the context of Null Space Labs without promoting it to an authenticated chat line.
3. **`enocia`: no matched public IRC transcript in the checked sources.** Focused searches combining this exact spelling with `IRC`, `#2600`, `2600net`, EFnet, and `shdwfear` did not produce a verified chat hit. GitHub's indexed code search for `enocia` restricted to `.log` returned **zero indexed results** at review time. Broad unqualified searches yielded unrelated organizations, games, and names; none were treated as the requested nick. Zero indexed results are not proof a nickname was never used.
4. **No authenticated joint conversation** involving `shdwfear` and `enocia` was recovered, on `#2600` or elsewhere. A directory, current user count, nickname listing, reposted fragment, or client-log statistic cannot supply the missing messages. [Archive Team describes IRC as transient and not universally logged](https://wiki.archiveteam.org/index.php/Archiveteam:IRC); public IRC log collections cover only some networks, channels and periods.

## What would change the result

A **network + channel + approximate year** for either handle, a verifiable log URL, or an owner-controlled mIRC/irssi/WeeChat/ZNC log would narrow the search. For a supplied private log, preserve raw bytes and hash, note source owner and timezone, distinguish JOIN/NAMES/QUIT from PRIVMSG/ACTION, and verify the network/channel per session. Keep private raw chat in the owner's storage, not the public repository. Do not infer that the two nicks are one person, try to deanonymize their operators, or equate a present-day nick registration with historic authorship.
