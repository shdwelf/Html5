🔍 HTML5 DOM Link Extractor & Frontier Generator

In this HTML5 port, link extraction is handled natively by the browser's built-in DOMParser and TreeWalker APIs, which parse full DOM trees with modern HTML5 forgiving-grammar rules and zero external dependencies.

📍 Subsurface GPX Gazetteer & Preservation

The older draft listed ten "historical SoCal caches" with names, GC codes and coordinates but no source GPX, listing-page evidence, or device dump. Those rows have been removed from the fixed compiled Gazetteer: the labels cannot be treated as verified records. Independent listing pages show clear ID/name mismatches for GC78 (Firestone, San Francisco Bay Area), GC40 (Namur, Belgium), and GC28 (Beverly, Illinois). The fixed Gazetteer now keeps GNIS/curated place data separate; cache points are added only from a user-provided GPX file.

Verified device and file-format boundary

  • The 2014 Geomate.jr User's Guide documents Pocket Query and raw-GPS GPX 1.1 input for the desktop loader. The same guide distinguishes the site's encrypted regional .cry files from GPX.
  • The Subsurface import accepts GPX 1.0/1.1 only. It does not decrypt proprietary .cry region files, write to the device, or flash firmware.
  • No Geomate.jr updater/firmware bytes were recovered in this audit, so there is no honest Geomate target for a Ghidra run. The modern GeoMate SG6/SG7 firmware is a different product family and is not used as a stand-in.

Session-only import and Xena-inspired preservation

Launch SoCal Subsurface 4Dwm and use the Gazetteer pane's local GPX controls. The page reads waypoints without a network call, draws only caches inside the SoCal theater, and keeps imported records in memory for the current session. It does not copy owner names, logs, hints or descriptions into the normalized register.

Xena is preservation-normalization software, not a universal filename/extension that this project can claim to emit. The optional BagIt 1.0 .zip preserves the original GPX byte-for-byte and adds an application-defined XML/JSON cache-register rendition, a preservation event note, and SHA-256 manifests. The .xdc is the offline viewer application package, not a GPX or Xena data file.
