# Headline Harry → Webxdc (ArcaneChat)

**Headline Harry and The Great Paper Race** (Davidson & Associates, DOS · 1991)
packaged as a [webxdc](https://webxdc.org) mini-app (`headline-harry.xdc`) that
runs inside ArcaneChat / Delta Chat — or any browser — completely offline.

## TL;DR

- Deliverable: **`../headline-harry.xdc`** (repo root, 2.75 MB) — send it as a file
  attachment in ArcaneChat and tap **Start**.
- It is not a recompilation. The original 1991 DOS binaries are bundled and booted
  by **js-dos 8.4.1** (DOSBox compiled to WebAssembly). See *"Why not Ghidra"*
  below for why a Ghidra→xdc conversion doesn't exist and what was done with
  Ghidra instead.

## Provenance

Source: Internet Archive item **`HeadlineHarry`**
(<https://archive.org/details/HeadlineHarry>) — four 720 kB FAT12 raw floppy
images. All four SHA-1-verified in the fetch workflow *and* locally:

```
77abc24ed8a401b23ef7ef769512f91c6e205b59  disk1.img
e7f468e2b3cda4066e003bb02c011e3227df16a6  disk2.img
ab4c1390f2c442069f04c151fa25f600dfd04f21  disk3.img
e134a66120ce989e1344dfb90d363eb2f36e2975  disk4.img
```

(Identical content to the TGOD Floppy Collection item
`002379-HeadlineHarryAndTheGreatPaperRace`.)

Boot sequence discovered from `HARRY.BAT`: `memtest` → `intro` → `map`.
The Webxdc bundle starts the recovered `MAP.EXE` directly: the packed floppy
EXEs are not runnable, and the standalone intro reaches a command-line stall
instead of handing control to the game. This launches at the U.S. Daily Star
**Press Pass** form; type a name and activate **OK** to continue.
`INTRO.EXE` is kept in the bundle for reference but skipped at boot; MEMTEST
would only gate the game on conventional-memory checks. The bundle contains the
**original installer-recovered `C:\HH` directory** (see *Recovery*):
`SETUP.INF` = VGA + AdLib, `HARRY.BAT`/`SETUP.BAT`/`INSTALL.EXE` kept untouched.

## Recovery (how the retail floppies became runnable files)

The 1991 floppies store game files **packed** (every EXE starts `ff 4d 5a`,
only `INSTALL.EXE` is clean) — key-disk style media. `INSTALL.INF` reveals a
script-driven unpacker that identifies disks only via per-disk CHECK_FILEs, so
the fetch workflow merges the four SHA-1-verified images into one `B:\` source
dir and drives the original installer through it unattended (DOSBox/Xvfb
keybot, VGA+AdLib chosen in its menus). The resulting `C:\HH` passes clean-`MZ`
checks (MAP.EXE 122,638→217,743 B, INTRO.EXE 47,851→82,525 B). The checked-in
Webxdc is built from these clean installer outputs, never from the packed
floppy EXEs. The workflow records DOSBox logs/screenshots under
`.xfer/harry/install/`; those artifacts are diagnostic and do not by themselves
prove that the game menu rendered. Ghidra consumes the recovered executables —
`ghidra/` holds the disassembly, decompilation, strings and metadata reports for
INTRO.EXE and MAP.EXE
(`ANALYSIS.md` summarizes; note: the tiny real-mode programs yield 0 named
functions in auto-analysis, so reports are linear disassembly + strings).

Audio: installed with **AdLib** (FM synthesis music). To use SoundBlaster
digitized audio instead, re-run `SETUP.BAT` inside the app (menu-driven).

## Pipeline (how this .xdc was built)

```
archive.org/HeadlineHarry  ──(GitHub runner; sandbox egress is allowlisted)──▶
.xfer/harry/disks/disk{1..4}.img  ──(mtools + original installer)──▶
.xfer/harry/installed/  ──(clean-MZ gate; fixed-date js-dos ZIP; MAP.EXE)──▶
app/roms/headline-harry.jsdos  ──(+ index.html + js-dos/ + icon + manifest)──▶
headline-harry.xdc (mirrored to webxdc-headline-harry/headline-harry.xdc)
```

Automation (both follow the repo's existing arena-* workflow patterns):

- `.github/workflows/arena-headline-harry.yml` — fetch + SHA-1 + FAT12 extract
  (trigger: change `.arena-relay/harry-fetch.txt`, or Actions → Run workflow)
- `.github/workflows/arena-headline-harry-ghidra.yml` — headless Ghidra analysis
  (trigger: change `.arena-relay/harry-ghidra.txt`, or manual)

## Why not "Ghidra → disassemble → convert to .xdc"

Ghidra disassembles machine code for *analysis*; it has no path that recompiles a
16-bit real-mode DOS game into HTML5/wasm, and a .xdc is a zip of web assets, not
a binary container. Porting properly means reverse-engineering the engine and
rewriting it (months of work). The practical, faithful "conversion" is emulation:
the original game runs under DOSBox→WASM. The packaged EXEs are the clean files
produced by the original installer, so they are **not byte-identical** to the
packed floppy entries (which begin `ff 4d 5a`). What Ghidra *is* good for here
it did: a documented static analysis of the recovered executables (`ghidra/` —
functions, strings, entry points, C pseudocode)
for anyone who does want to study or eventually port the engine.

## Rebuild

```bash
./build-xdc.sh          # needs .xfer/harry/installed with clean INTRO/MAP MZ files
                         # rebuilds both XDC copies; refuses packed raw floppy EXEs
```

## In ArcaneChat

1. Send `headline-harry.xdc` into any chat (attach → file).
2. Tap it → **Start**. Tap **BOOT THE PRESSROOM**.
3. Desktop: mouse + keyboard. Android: js-dos' ☰ sidebar has the on-screen
   keyboard; volume/hardware keyboard also works.
4. Saves/high scores live only for the session (webxdc apps are offline and
   stateless by design).
