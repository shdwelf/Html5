Lantronix,
µClinux and the wallplug

One device — a thumb-sized Lantronix serial-to-Ethernet module with 16 MB of flash — pulls five threads together: the µClinux stack it runs, the Ghidra work needed to match an unknown firmware blob to its processor and kernel, the DistroWatch question about what else could run on that silicon, the Java side (JVM bytecode, Java Card, a wiki that ships as a jar, and ACME's tiny web servers), and the EAGLE design for a mains-powered wallplug that carries it. Every panel below runs in this tab: the triage tool and the class-file reader parse your bytes locally, and the EDA view renders the generated .sch/.brd and re-runs the design-rule checks in the browser. Companion write-up: docs/lantronix-uclinux-deep-dive-2026-10-08.md.

Lantronix serial-to-Ethernet families

—

The part that matters for reverse engineering is the silicon: Lantronix's DSTni-EX is an x86-class 16-bit core that runs Evolution OS, and the DSTni-FX is a Freescale ColdFire that runs either Evolution OS or the vendor's µClinux. Same RJ45, same 8-pin serial header, two completely different Ghidra languages.

    What Lantronix actually ships

    SDK 900-548

    The Linux SDK for MatchPort AR / xPort Pro / EDS1100-2100 is a µClinux-dist tree: patched kernel, uClibc, BusyBox and a hand-picked userland, built with a CodeSourcery m68k-uclinux toolchain, booted by a two-stage loader (read-only Lantronix stage + dBUG), with a ROMFS root and an optional JFFS2 partition in 16 MB of parallel flash.
