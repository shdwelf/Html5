The protocol

Why Z39.50 still matters

Z39.50 is an application-layer information-retrieval protocol. An origin opens an association with a target, negotiates capabilities, sends a Type-1/RPN query, receives a result-set count, then requests records with Present.

01
InitializeNegotiate version, options, character set, authentication and preferred record syntax.
02
SearchSend Bib-1 attributes such as use=title or use=author. The target creates a named result set.
03
PresentRequest a range and syntax: MARC-21, MARCXML, XML, SUTRS or another agreed format.
04
CloseRelease the association and persist provenance: host, database, query, timestamp, syntax.
Vocabulary

Terms worth getting right

  • Origin — client
  • Target — server endpoint
  • OID — object identifier
  • Bib-1 — search attributes
  • RPN — reverse Polish query
  • Result set — server-side hits
  • Present — record retrieval
  • MARC-21 — bibliographic syntax
  • SRU — search/retrieve via URL
  • Explain — target capabilities
The standard TCP port is 210, but port numbers are configuration—not identity. Always use the provider's current hostname and database name.
Build plan

Correct client architecture

1 · Browser UI

Collect target, database, query fields, syntax and credentials. Never put library credentials in a static HTML file.

2 · Protocol gateway

Use a backend or desktop/native adapter for ASN.1 BER encoding and the Z39.50 Initialize, Search, Present and Close PDUs. Browser fetch cannot open arbitrary TCP port 210.

3 · Normalizer

Convert MARC-21/MARCXML into one display model, preserving the raw record and the target's provenance.

4 · Safety

Rate-limit, cap result windows, escape MARC text, redact credentials from logs, and respect each provider's terms.

Minimal adapter contract

Keep the UI transport-agnostic

POST /api/z3950/search
{
  "host": "lx2.loc.gov",
  "port": 210,
  "database": "LCDB",
  "query": { "use": "title", "term": "neural networks" },
  "syntax": "MARCXML",
  "start": 1,
  "count": 10
}

→ { "hits": 123, "records": [...], "diagnostics": [] }

For a real deployment, place this contract behind authentication and an allowlist of approved targets. The included SRU search demonstrates the same UI without pretending to implement BER.
