The thesis

Augmentation beats replacement

The strongest pattern for a GitHub project is a narrow, observable loop: retrieve the right repository context, ask a language model to propose a change, then let deterministic checks and a compact neural scorer rank the result.

Reference architecture

Keep the trust boundary explicit

A production implementation should put the OpenAI call behind a server-side proxy. The browser can inspect the pipeline, but never receives a permanent API key.

Failure modes

Design against confident nonsense

Prompt injection in issues

Treat repository text as untrusted data. Tools enforce allowlists; instructions never come from retrieved files.

Reward hacking

Never train the verifier only on “merged.” Include reverted patches and flaky-test outcomes.

Silent drift

Pin model versions, record commit SHA and prompt schema, and compare calibration over time.

Privacy

Minimize context, redact secrets, and offer an offline mode for sensitive repositories.

Why it belongs here

The verifier should be small enough to audit: features in, score out, confidence calibrated against held-out outcomes. Keep generative reasoning and deterministic evaluation separate.
